# Query performance evidence

Generated by `make bench` (7 runs per variant after a warm-up; median execution time from `EXPLAIN (ANALYZE, BUFFERS)`). PostgreSQL 16 in Docker on a laptop: compare the ratios, not the absolute times.

| Benchmark | Change | Before | After | Speed-up | Buffers before → after |
|---|---|---:|---:|---:|---:|
| Every event by Lionel Messi, in match order | `event_player_idx` | 12.75 ms | 1.1 ms | ×11.6 | 4,141 → 403 |
| Replay one possession of the final | `event_match_possession_idx` | 0.46 ms | 0.06 ms | ×7.7 | 100 → 8 |
| Every pass Messi received | `pass_recipient_idx` | 3.25 ms | 0.31 ms | ×10.5 | 1,068 → 131 |
| Pass network of the final: live view vs materialized view + index on match_id | query rewrite | 1014.56 ms | 0.06 ms | ×16909.3 | 470,615 → 5 |
| Live pass-network query with a candidate index (rejected: the materialized view supersedes it) | candidate index (not kept) | 1017.89 ms | 743.36 ms | ×1.4 | 470,607 → 570,791 |
| Control: whole-tournament team xG table (a full aggregation; no index should help) | `event_player_idx`, `event_match_possession_idx`, `pass_recipient_idx` | 147.31 ms | 148.02 ms | ×1.0 | 16,736 → 16,736 |
| Team xG table: correlated subqueries per team vs one aggregate per CTE | query rewrite | 1196.04 ms | 146.31 ms | ×8.2 | 1,082,328 → 16,736 |
| Game state for all 64 matches: correlated subqueries vs one window pass | query rewrite | 932.78 ms | 40.31 ms | ×23.1 | 93,176 → 4,378 |
